# Competitions Phase 7 — Security, Regression & Release Readiness

## Automated release gates

- `pnpm verify:competitions-phase7` audits public/private competition routing, row-scoped competition changes, public-only media and match-stat filtering, stable server pagination, and the **physical top-left 144 × 144 photo** layout regression. It is included in root `pnpm verify` together with earlier Phases 1–6 and the complete typecheck/test/build suite.
- `apps/api/test/competition-phase7-security.test.ts` tests organizer cross-venue denial, unpublished competition privacy, private payment reference redaction, accepted-team-only match stats, manager/member My Competitions parity, private discovery scopes, and 15-result/3-page pagination correctness.
- `.github/workflows/qa-competition-db.yml` runs on competition-related PRs and main changes. It initializes a **throwaway Postgres 18** with every migration, exercises the existing seed-story DB smoke tests, and runs `pnpm --filter @leaguekick/api exec tsx scripts/competition-phase7-db.ts`. That script refuses any DB outside CI + local `futsal_ci`, then uses the real Drizzle repository to test 3 simultaneous approvals for 2 slots, a simultaneous acceptance/capacity-shrink conflict, owner/public media visibility, latest PUBLIC photo precedence, manager visibility without membership rows, and public fee redaction.
- Back-end consistency fixes: competition-list accepted counts fetched as **one grouped query**, published fallback photo fetched as **one latest PUBLIC row per competition**, and competition manager listings now include owning managers without duplicated memberships. Both approvals and max-team reductions lock the competition row in transactions.
- UI resilience fix: failed 'Show More' no longer destroys successfully fetched results. Existing page remains and the button becomes Retry; expired response IDs cannot overwrite a new filter query.

## Manual Expo Go / responsive release checklist (not automatically signed off)

1. **English** — on Android Expo Go, open Competitions at phone width, apply search/status/city/fee/date filters, then Show More; verify no duplicates and no stale results. Disconnect network while fetching the next page: already loaded cards remain visible, a non-blocking error appears, Retry works after reconnecting.
2. **Dari/Pashto RTL** — repeat search/filter/pagination in both languages. Ensure the competition photo is still a **square in the physical top-left** (not flipped to the right), name/venue stay beside it, metadata below; the selected navigation tab remains focused and visible.
3. **Tablet / desktop** — check widths just below and above **720 px** for 1-column/2-column layout, no horizontal overflow, readable date/fee chips, large-text accessibility sizing, button touch targets and no image distortion.
4. **Cross-role** — test as normal user, player, team manager, host venue owner and a different venue owner. Normal users can see published public competitions; team managers can see their own team registrations even without an ACTIVE membership record; only the host organizer can edit settings/images, see private fee references or manage media; drafts do not appear in public search/deep links.
5. **Concurrency / payments** — organizers approve simultaneous pending teams near capacity; no extra participant can be accepted. Shrink maximum teams at the same time as accepting a pending team; final accepted count must not exceed stored cap. Sensitive payment reference remains host-owner-only.
6. **Match details / feeds** — match statistics remain limited to accepted teams and completed/corrected matches; draft or private posts/images do not appear in public updates or directory covers. Existing photo galleries, standings, group stages, bracket progress, score correction and team links remain functional.
7. **Branding** — upload/replace/delete square logos and wide banners, verify crop, preview and the card/header independently; duplicated competitions remain unbranded. Check image access/permission error messages in all three languages.
8. **Time** — validate Kabul-local date/day and AM/PM formatting on competition cards, match details and booking destinations. Verify that switching tabs, returning to lists and refresh actions never lose the user's intended screen.
9. **Operational release** — apply all pending migrations (through `0041_competition_branding`) **before** API deployment, deploy mobile and API compatibly, confirm no 401/403/500 for intended actor roles; keep logs on rate-limits, request failures and image uploads.

A passing GitHub CI gate does **not** constitute completion of the physical device/manual checklist. Record device, build, language, date, screenshots and pass/fail findings before production signoff.
